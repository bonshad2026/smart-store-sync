# فروشگاه‌یار هوشمند (Smart Store Sync) — نسخه اولیه (MVP)

سامانه مدیریت متمرکز محصولات، همگام‌سازی قیمت و موجودی، تولید محتوای تبلیغاتی با هوش مصنوعی و انتشار کنترل‌شده در تلگرام.

## قابلیت‌های نسخه اولیه (مطابق بخش ۹ سند)

| # | قابلیت | محل پیاده‌سازی |
|---|--------|----------------|
| ۱ | دریافت اطلاعات محصولات از فایل CSV | `backend/src/services/csvImport.ts` — صفحه «محصولات» ← «ورود از CSV» |
| ۲ | نگهداری محصولات در پایگاه داده مرکزی | PostgreSQL — `backend/src/db/schema.sql` |
| ۳ | شناسایی تغییرات قیمت و موجودی | `backend/src/services/products.ts` (جدول `product_changes`) |
| ۴ | تولید متن تبلیغاتی با هوش مصنوعی | `backend/src/services/ai.ts` (وب‌سایت، اینستاگرام، تلگرام، اطلاعیه تخفیف) |
| ۵ | ارسال محتوای تأییدشده به کانال تلگرام | `backend/src/services/telegram.ts` — فقط پس از تأیید انسانی |
| ۶ | داشبورد ساده (محصولات، وضعیت عملیات، خطاها) | `frontend/` (React + TypeScript، فارسی و راست‌چین) |
| ۷ | ثبت سوابق عملیات و تلاش مجدد | `backend/src/services/operations.ts` و `retry.ts` — صفحه «تاریخچه عملیات» |

## ساختار پروژه

```
smart-store-sync/
├── backend/            API با Node.js + TypeScript + Express
│   └── src/
│       ├── db/         schema.sql، اتصال، migrate و seed
│       ├── routes/     مسیرهای API
│       └── services/   منطق کسب‌وکار (محصولات، AI، تلگرام، همگام‌سازی، عملیات)
├── frontend/           داشبورد مدیریتی React + TypeScript (Vite)
├── n8n/workflows/      گردش‌کارهای آماده n8n برای import
├── sample-data/        فایل CSV نمونه
├── docker-compose.yml  PostgreSQL + برنامه + n8n
└── .env.example        نمونه تنظیمات
```

## راه‌اندازی سریع با Docker (پیشنهادی)

پیش‌نیاز: Docker Desktop

```bash
cd "C:\My Job\smart-store-sync"
copy .env.example .env        # سپس .env را ویرایش کنید
docker compose up -d --build
```

- داشبورد و API: http://localhost:4000
- n8n: http://localhost:5678

## راه‌اندازی بدون Docker (حالت توسعه)

پیش‌نیاز: Node.js 20 یا بالاتر، PostgreSQL 14 یا بالاتر

```bash
# ۱) یک پایگاه داده بسازید و مشخصات آن را در .env (پوشه اصلی پروژه) وارد کنید
copy .env.example .env

# ۲) بک‌اند
cd backend
npm install
npm run seed        # ساخت جداول + وارد کردن محصولات نمونه (اختیاری)
npm run dev         # http://localhost:4000/api

# ۳) داشبورد (در ترمینال جدید)
cd frontend
npm install
npm run dev         # http://localhost:5173
```

## تنظیمات مهم (`.env`)

| متغیر | توضیح |
|-------|-------|
| `AI_API_KEY`، `AI_BASE_URL`، `AI_MODEL` | هر سرویس سازگار با OpenAI Chat Completions. اگر خالی باشد، متن‌ها با **قالب آماده** ساخته می‌شوند تا سیستم بدون AI هم قابل استفاده باشد. |
| `TELEGRAM_BOT_TOKEN` | توکن ربات از ‎@BotFather. ربات باید ادمین کانال باشد. |
| `TELEGRAM_CHAT_ID` | شناسه کانال (مثل ‎`@my_channel`). از صفحه تنظیمات هم قابل تغییر است. |
| `API_KEY` | کلید مشترک برای n8n و داشبورد (هدر `x-api-key`). در محیط واقعی حتماً تنظیم شود. |
| `N8N_WEBHOOK_URL` | اگر تنظیم شود، تغییرات محصول به‌جای پردازش داخلی به n8n ارسال می‌شود. |

کلیدها و توکن‌ها فقط سمت سرور نگهداری می‌شوند.

## گردش‌کار سیستم

1. محصول در پنل ویرایش یا از CSV وارد می‌شود.
2. بک‌اند تغییر قیمت، قیمت تخفیفی، موجودی یا مشخصات را تشخیص می‌دهد و در `product_changes` ثبت می‌کند.
3. داده‌ها اعتبارسنجی و در پایگاه داده ذخیره می‌شوند.
4. گردش‌کار n8n اجرا می‌شود (یا اگر n8n تنظیم نشده باشد، بک‌اند خودش ادامه می‌دهد).
5. متن تبلیغاتی جدید فقط بر اساس اطلاعات واقعی محصول تولید می‌شود.
6. محتوا با وضعیت «در انتظار بررسی» در داشبورد نمایش داده می‌شود.
7. پس از تأیید (و در زمان تعیین‌شده)، محتوا در کانال تلگرام منتشر می‌شود.
8. نتیجه هر عملیات در «تاریخچه عملیات» ثبت می‌شود و عملیات ناموفق قابل تلاش مجدد است.

## n8n

1. وارد n8n شوید (http://localhost:5678).
2. از منوی **Workflows ← Import from File** فایل‌های پوشه `n8n/workflows` را وارد کنید:
   - `01-product-changed.json`: دریافت تغییر محصول ← انتخاب کانال ← تولید محتوا ← علامت‌گذاری تغییرات.
   - `02-publish-and-retry.json`: هر ۱۰ دقیقه تلاش مجدد عملیات ناموفق و انتشار محتوای زمان‌بندی‌شده.
3. گردش‌کارها را فعال کنید و در `.env` مقدار `N8N_WEBHOOK_URL=http://n8n:5678/webhook/product-changed` را قرار دهید.

## فرمت فایل CSV

```csv
sku,name,description,price,discount_price,stock,category,image_url,color,size
TSH-001,تی‌شرت نخی,توضیحات...,500000,450000,25,پوشاک,,سفید,L
```

- ستون‌های `sku`، `name`، `price` و `stock` الزامی هستند.
- اعداد فارسی و جداکننده هزارگان (مثل ۴۵۰٬۰۰۰) پشتیبانی می‌شوند.
- ستون‌های اضافی (رنگ، سایز، برند و…) به‌عنوان ویژگی‌های محصول ذخیره و در تولید محتوا استفاده می‌شوند.
- با وارد کردن دوباره فایل، محصولات بر اساس `sku` به‌روزرسانی و تغییرات شناسایی می‌شوند.

## API اصلی

| متد | مسیر | توضیح |
|-----|------|-------|
| GET | `/api/health` | وضعیت سرویس و اتصال‌ها |
| GET | `/api/dashboard` | آمار داشبورد |
| GET/POST | `/api/products` | فهرست / ایجاد یا به‌روزرسانی محصول (بر اساس SKU) |
| PUT/DELETE | `/api/products/:id` | ویرایش / حذف |
| POST | `/api/products/import` | ورود CSV (فیلد `file`) |
| GET | `/api/changes` | تاریخچه تغییرات |
| POST | `/api/contents/generate` | `{ productId, channels: ["telegram","instagram","website","discount"] }` |
| PATCH | `/api/contents/:id` | ویرایش متن، تأیید/رد، زمان‌بندی |
| POST | `/api/contents/:id/publish` | انتشار فوری محتوای تأییدشده |
| POST | `/api/contents/publish-due` | انتشار محتوای زمان‌رسیده |
| GET | `/api/operations` | تاریخچه عملیات |
| POST | `/api/operations/:id/retry` | تلاش مجدد |
| GET/PUT | `/api/settings` | تنظیمات فروشگاه و لحن برند |

## گام‌های بعدی (پس از MVP)

- اتصال مستقیم به فروشگاه‌ها (ووکامرس و…) به‌عنوان منبع محصولات
- انتشار در اینستاگرام از طریق API رسمی (بسته به نوع حساب و مجوزها)
- مدیریت کاربران و چند فروشگاه (multi-tenant) برای مدل اشتراکی
- کنترل هزینه مصرف AI برای هر فروشگاه و گزارش‌های پیشرفته
